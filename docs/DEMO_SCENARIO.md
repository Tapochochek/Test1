# Сценарий демонстрации прототипа

Ожидаемая продолжительность: 5–7 минут. Все демо-данные вымышлены.

## 1. Вход и роли

1. Открыть `http://localhost:8080`.
2. Войти под `federation@fsp56.ru`, пароль `demo`.
3. Показать, что роль Федерации видит создание и публикацию соревнований, реестр и модерацию заявок.
4. Выйти и войти как `morozov@fsp56.ru`, пароль `demo`. У этой учётной записи назначены роли спортсмена и тренера; активную роль можно менять только между назначенными ролями.
5. Показать форму публичной регистрации. В качестве роли можно выбрать спортсмена, тренера или судью; самостоятельно зарегистрировать Федерацию нельзя.

## 2. Создать и опубликовать соревнование

1. Под ролью Федерации открыть «Соревнования» и нажать «Создать соревнование».
2. Указать название, дисциплину и тип из серверного справочника, уровень, формат, возрастную группу, дату, место, срок заявок, календарный план и положение соревнования.
3. Сохранить черновик, затем нажать «Опубликовать».
4. Проверить, что статус изменился на «Регистрация».

## 3. Регистрация спортсмена и подтверждение профиля

1. Выйти и создать новый аккаунт спортсмена. Для теста указать дату рождения, возрастную группу и дисциплину, совпадающие с соревнованием.
2. Подтвердить согласие на обработку персональных данных. Для несовершеннолетнего спортсмена также заполнить ФИО законного представителя и его согласие.
3. Войти под Федерацией и открыть «Реестр участников».
4. Нажать «Подтвердить» рядом с профилем со статусом «На проверке».

## 4. Заявка и модерация

1. Войти под подтверждённым спортсменом.
2. Открыть «Соревнования» и подать заявку на соревнование со статусом «Регистрация», у которого совпадают дисциплина и возрастные условия.
3. Вернуться под Федерацией, открыть «Соревнования» и обработать заявку в блоке «Заявки на рассмотрении».
4. Одобрить заявку. Счётчик участников соревнования обновляется на основе одобренных заявок.

## 5. Результаты и роли

- Федерация может назначить судью через API и сохранять результаты.
- Судья может сохранять результаты только соревнования, на которое он назначен Федерацией.
- Результаты и протоколы доступны через API; полноценный экран ввода результатов и отдельные рабочие экраны тренера/судьи ещё требуют доработки.
- В разделе «Документы» проверить выгрузку протокола DOCX/XLSX, отчёта спортсмена DOCX, реестра XLSX, отчёта о численности XLSX и проекта приказа DOCX.
- В разделе «Рейтинг» проверить фильтр по возрастной группе и дисциплине; в «Сборной области» проверить фильтры кандидатов, ручной выбор и сохранение состава.
- Новые профили спортсменов ожидают подтверждения; пока профиль не подтверждён, заявка на соревнование отклоняется сервером.

## Запуск и проверка

```bash
docker compose up --build
```

- Веб-интерфейс: `http://localhost:8080`
- API health: `http://localhost:8081/api/health`

Для локальной проверки API сначала выполните вход и используйте полученный токен в заголовке `Authorization: Bearer <token>`. Например:

```bash
curl -X POST http://localhost:8081/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"federation@fsp56.ru","password":"demo"}'
```

## Ограничения прототипа

Перед реальной эксплуатацией нужно прогнать интеграционные тесты регистрации и ролевого доступа, проверить все бизнес-сценарии на развёрнутом стенде, завершить UI ввода результатов и рабочие формы привязки/назначений/разрядов/категорий, сверить шаблоны документов и официальный регламент рейтинга, добавить rate limiting и проверить конфигурацию секретов. Не использовать демонстрационные пароли в публичном развёртывании.

## 6. Проверка оформления

1. На экране входа нажать переключатель темы: режимы циклически меняются между «Авто», «Светлая» и «Тёмная».
2. В режиме «Авто» оформление следует настройке светлой/тёмной темы операционной системы и обновляется при её изменении.
3. Выбранная вручную тема сохраняется после перезагрузки страницы; выбор «Авто» возвращает системное управление.
4. Проверить логотип ФСП на экране входа и в боковой панели, а также светлую/тёмную темы на мобильной ширине.
5. Надпись рядом с индикатором обновления должна различать данные, загруженные из API, и демонстрационные данные при недоступности API.
